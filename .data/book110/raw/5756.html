그림 17.21 opt10081을 이용한 주식 일봉 차트 조회 요청

OpenAPI+가 제공하는 TR을 사용하려면 먼저 SetInputValue 메서드를 통해 요청하는 TR에 필요한 데이터를 설정한 후 CommRqData 메서드를 호출해 TR을 키움증권 서버로 전송하면 됩니다. TR을 요청 받은 서버는 이를 처리한 후 데이터가 준비되면 이벤트를 발생시켜 사용자가 데이터를 가져갈 수 있게 알려줍니다.

이번 절에서는 Kiwoom 클래스에 TR을 쉽게 사용할 수 있도록 몇 개의 메서드를 추가해 보겠습니다. 이번 절에서 작성할 전체 코드는 예제 17.3과 같습니다. 코드가 길어 보이지만 Kiwoom 클래스의 대부분은 앞에서 작성했습니다.

import sys
from PyQt5.QtWidgets import *
from PyQt5.QAxContainer import *
from PyQt5.QtCore import *
import time

TR_REQ_TIME_INTERVAL = 0.2

class Kiwoom(QAxWidget):
    def __init__(self):
        super().__init__()
        self._create_kiwoom_instance()
        self._set_signal_slots()

    def _create_kiwoom_instance(self):
        self.setControl("KHOPENAPI.KHOpenAPICtrl.1")

    def _set_signal_slots(self):
        self.OnEventConnect.connect(self._event_connect)
        self.OnReceiveTrData.connect(self._receive_tr_data)

    def comm_connect(self):
        self.dynamicCall("CommConnect()")
        self.login_event_loop = QEventLoop()
        self.login_event_loop.exec_()

    def _event_connect(self, err_code):
        if err_code == 0:
            print("connected")
        else:
            print("disconnected")

        self.login_event_loop.exit()

    def get_code_list_by_market(self, market):
        code_list = self.dynamicCall("GetCodeListByMarket(QString)", market)
        code_list = code_list.split(';')
        return code_list[:-1]

    def get_master_code_name(self, code):
        code_name = self.dynamicCall("GetMasterCodeName(QString)", code)
        return code_name

    def set_input_value(self, id, value):
        self.dynamicCall("SetInputValue(QString, QString)", id, value)

    def comm_rq_data(self, rqname, trcode, next, screen_no):
        self.dynamicCall("CommRqData(QString, QString, int, QString", rqname, trcode, next, screen_no)
        self.tr_event_loop = QEventLoop()
        self.tr_event_loop.exec_()

    def _comm_get_data(self, code, real_type, field_name, index, item_name):
        ret = self.dynamicCall("CommGetData(QString, QString, QString, int, QString", code,
                               real_type, field_name, index, item_name)
        return ret.strip()

    def _get_repeat_cnt(self, trcode, rqname):
        ret = self.dynamicCall("GetRepeatCnt(QString, QString)", trcode, rqname)
        return ret

    def _receive_tr_data(self, screen_no, rqname, trcode, record_name, next, unused1, unused2, unused3, unused4):
        if next == '2':
            self.remained_data = True
        else:
            self.remained_data = False

        if rqname == "opt10081_req":
            self._opt10081(rqname, trcode)

        try:
            self.tr_event_loop.exit()
        except AttributeError:
            pass

    def _opt10081(self, rqname, trcode):
        data_cnt = self._get_repeat_cnt(trcode, rqname)

        for i in range(data_cnt):
            date = self._comm_get_data(trcode, "", rqname, i, "일자")
            open = self._comm_get_data(trcode, "", rqname, i, "시가")
            high = self._comm_get_data(trcode, "", rqname, i, "고가")
            low = self._comm_get_data(trcode, "", rqname, i, "저가")
            close = self._comm_get_data(trcode, "", rqname, i, "현재가")
            volume = self._comm_get_data(trcode, "", rqname, i, "거래량")
            print(date, open, high, low, close, volume)

이번에는 comm_rq_data 메서드를 추가해 보겠습니다. 이를 위해 OpenAPI+ 개발 가이드에서 CommRqData 메서드의 원형을 살펴보겠습니다. 그림 17.23과 같이 네 개의 메서드 인자를 받는 것을 확인할 수 있습니다.

그림 17.23 CommRqData 메서드(출처: 키움 OpenAPI+ 개발가이드)

다음 코드와 같이 Kiwoom 클래스에 comm_rq_data 메서드를 구현합니다. comm_rq_data는 self.dynamicCall 메서드를 이용해 OpenAPI+의 CommRqData 메서드를 호출하는 코드와 QEventLoop 클래스의 인스턴스를 생성한 후 이벤트 루프를 만드는 코드로 구성됩니다.

CommRqData를 통해 키움증권 서버에 TR을 요청하면 데이터가 바로 반환되는 것이 아닙니다. 키움증권 서버는 TR을 처리한 후 이벤트를 통해 알려주기 때문에 키움증권이 이벤트를 줄 때까지 대기하고 있어야 합니다. 따라서 CommRqData를 호출한 후에 이벤트 루프를 만들어주는 코드가 반드시 있어야 합니다. 이 부분은 앞서 로그인을 수행할 때 이벤트 루프를 만든 것과 동일합니다.

def comm_rq_data(self, rqname, trcode, next, screen_no):

    self.tr_event_loop = QEventLoop()
    self.tr_event_loop.exec_()

키움증권 서버에 TR을 요청하면 한 번에 여러 개의 데이터가 반환됩니다. 예를 들어, opt10081을 통해 일봉 데이터를 요청하는 경우 약 900개의 데이터(거래일 기준)가 반환됩니다. 데이터를 받는 입장에서는 총 몇 개의 데이터가 왔는지 알고 있어야 for나 while과 같은 반복문을 통해 데이터를 읽을 수 있습니다. 이러한 용도로 사용하는 메서드가 _get_repeat_cnt입니다. 역시 OpenAPI+의 개발 가이드를 참조해서 다음과 같이 Kiwoom 클래스에 구현합니다.

def _get_repeat_cnt(self, trcode, rqname):
    ret = self.dynamicCall("GetRepeatCnt(QString, QString)", trcode, rqname)
    return ret

키움증권 서버로부터 TR 처리에 대한 이벤트가 발생했을 때 실제로 데이터를 가져오려면 CommGetData 메서드를 사용해야 합니다. 역시 OpenAPI+의 개발 가이드를 참조해서 다음과 같이 _comm_get_data 메서드를 Kiwoom 클래스에 구현합니다. OpenAPI+의 CommGetData 메서드의 반환값은 문자열 타입 로 양쪽에 공백이 있습니다. 따라서 공백을 제거하기 위해 반환받은 문자열에 strip 메서드를 사용했습니다.

def _comm_get_data(self, code, real_type, field_name, index, item_name):
    ret = self.dynamicCall("CommGetData(QString, QString, QString, int, QString", code,
                           real_type, field_name, index, item_name)
    return ret.strip()

마지막으로 이벤트가 발생했을 때 이를 처리하는 메서드를 구현하겠습니다. OpenAPI+ 개발 가이드를 참조하면 TR 요청의 결과로 OnReceiveTrData 이벤트가 발생합니다. 개발 가이드를 참조해서 다음과 같이 동일한 이름으로 메서드를 정의합니다.

def _receive_tr_data(self, screen_no, rqname, trcode, record_name, next, unused1, unused2, unused3, unused4):
    pass

위에서 구현한 _receive_tr_data라는 메서드가 'OnReceiveTrData' 이벤트가 발생할 때 호출되게 하려면 시그널과 슬롯을 연결해 주면 되지요? 다음과 같이 _set_signal_slots 메서드를 수정합니다. 

def _set_signal_slots(self):
    self.OnEventConnect.connect(self._event_connect)
    self.OnReceiveTrData.connect(self._receive_tr_data)

Kiwoom 클래스 내부에 구현한 _receive_tr_data 메서드가 호출됐다는 것은 키움증권 서버로부터 'OnReceiveTrData' 이벤트가 발생했음을 의미합니다. 따라서 _receive_tr_data 메서드 내에서 서버로부터 데이터를 받아오면 됩니다. 앞서 메서드의 원형만 구현했던 _receive_tr_data 메서드를 다음과 같이 수정해줍니다. 

def _receive_tr_data(self, screen_no, rqname, trcode, record_name, next, unused1, unused2, unused3, unused4):
    if next == '2':
        self.remained_data = True
    else:
        self.remained_data = False

    if rqname == "opt10081_req":
        self._opt10081(rqname, trcode)

    try:
        self.tr_event_loop.exit()
    except AttributeError:
        pass

_receive_tr_data 메서드를 구현할 때는 다음 세 가지를 고려해야 합니다.

첫 번째는 여러 종류의 TR을 요청해도 모두 _receive_tr_data 메서드 내에서 처리해야 한다는 것입니다. 따라서 rqname이라는 인자를 통해 요청한 TR을 구분한 후 TR에 따라 적당한 데이터를 가져오도록 코드를 작성해야 합니다.

위 코드를 살펴보면 if 구문을 사용해 rqname 값이 'opt10081_req'일 때 _opt10081 메서드를 호출하는 것을 확인할 수 있습니다. 이처럼 TR을 요청할 때 여러분이 TR을 구분하기 위한 적당한 문자열을 사용하고, 데이터를 받을 때는 해당 문자열과 같은지 확인함으로써 올바른 데이터를 얻을 수 있습니다.

두 번째는 연속조회에 대한 처리입니다. 연속조회는 아직 데이터가 더 존재한다는 것을 의미합니다. 예를 들어, 10년 치 일봉 차트 데이터가 존재한다면 데이터의 개수가 수천 개에 이를 것입니다. 앞서 TR을 한 번 요청하면 900개의 데이터가 반환된다고 했으므로 10년 치 데이터를 한 번의 TR 요청으로는 받을 수 없습니다. 이런 경우에는 연속해서 같은 TR을 또 요청해서 남아있는 데이터를 받아야 합니다.

키움증권 서버는 OnReceiveTrData 이벤트가 발생할 때 PrevNext라는 인자 값을 통해 연속조회가 필요한 경우 PrevNext 값을 2로 리턴합니다. 따라서 PrevNext 값을 보고 그 값이 2이면 아직 데이터가 더있다는사실을알수있고,이경우동일한TR을한번더요청해서남은데이터를가져와야합니다. 위 코드에서는 _receive_tr_data 메서드의 인자인 next의 값이 '2'일 때 self.remained_data라는 변수에 True를 저장합니다. 이 값을 보고 TR을 더 요청하는 코드는 조금 후에 다시 설명하겠습니다.

세 번째 고려사항은 이벤트 루프에 대한 처리입니다. 앞서 CommRqData를 호출할 때 이벤트 루프를 생성했습니다. 이벤트 루프 덕분에 키움증권 서버가 'OnReceiveTrData' 이벤트를 보낼 때까지 대기할 수 있었습니다.

Kiwoom 클래스의 _receive_tr_data 메서드가 호출됐다는 것은 여러분이 구현한 프로그램이 정상적으로 대기 상태에서 머무르다가 서버로부터 발생한 'OnReceiveTrData' 이벤트를 받았음을 의미합니다. 따라서 _receive_tr_data 메서드에서는 더는 필요하지 않은 이벤트 루프를 종료하면 됩니다. 

try:
    self.tr_event_loop.exit()
except AttributeError:
    pass

_receive_tr_data 메서드에서 데이터를 얻어오는 부분을 살펴보겠습니다. opt10081_req에 대한 데이터는 _opt10081 메서드에서 처리합니다. 이는 각 TR에 대한 데이터를 얻어가는 코드를 _receive_tr_data에 모두 구현하기 보다는 메서드로 따로 빼서 구현한 것입니다.

앞서 TR을 요청하면 약 900개의 데이터가 반환된다고 했는데 데이터가 그보다 적다면 더 적은 수가 리턴될 것입니다. 예를 들어, 상장한 지 얼마 되지 않은 종목이 여기에 해당할 것입니다. 따라서 데이터를 얻어오기 전에 먼저 데이터의 개수를 _get_repeat_cnt 메서드를 통해 얻어옵니다.

def _opt10081(self, rqname, trcode):
    data_cnt = self._get_repeat_cnt(trcode, rqname)

데이터의 총 개수를 얻었다면 반복문을 통해 데이터를 하나씩 얻어오면 됩니다. 일봉 데이터는 거래일 단위로 ‘종목코드’, ‘현재가’, ‘거래량’, ‘거래대금’, ‘일자’, ‘시가’, ‘고가’, ‘저가’, ‘수정주가구분’, ‘수정비율’, ‘대업종구분’, ‘소업종구분’, ‘종목정보’, ‘수정주가이벤트’, ‘전일종가’를 한 번에 제공합니다. 여기서는 ‘일자’, ‘시가’, ‘고가’, ‘저가’, ‘현재가’, ‘거래량’만 필요하므로 다음과 같이 코드를 작성하면 됩니다.

def _opt10081(self, rqname, trcode):
    data_cnt = self._get_repeat_cnt(trcode, rqname)

    for i in range(data_cnt):
        date = self._comm_get_data(trcode, "", rqname, i, "일자")
        open = self._comm_get_data(trcode, "", rqname, i, "시가")
        high = self._comm_get_data(trcode, "", rqname, i, "고가")
        low = self._comm_get_data(trcode, "", rqname, i, "저가")
        close = self._comm_get_data(trcode, "", rqname, i, "현재가")
        volume = self._comm_get_data(trcode, "", rqname, i, "거래량")
        print(date, open, high, low, close, volume)

이로써 opt10081 TR을 사용할 수 있도록 Kiwoom 클래스를 업데이트했습니다. 이번에는 Kiwoom 클래스를 사용해 실제로 일봉 데이터를 얻어오는 코드를 작성해 보겠습니다. 먼저 QApplication 클래스 인스턴스와 Kiwoom 클래스 인스턴스를 생성한 후 로그인을 수행하는 코드는 앞의 예제와 같습니다.

app = QApplication(sys.argv)
kiwoom = Kiwoom()
kiwoom.comm_connect()

연속조회가 가능한 TR의 처리는 다음과 같이 코드를 작성하면 됩니다. ‘종목코드’에 실제로 조회할 종목 코드를 입력하고, ‘기준일자’ 항목에는 조회를 시작할 일자에 대해 '20170224'와 같은 형식으로 입력하면 됩니다. ‘수정주가구분’에는 1을 입력해서 수정주가를 요청했습니다.

comm_rq_data 메서드를 호출할 때 주의할 점은 첫 번째 인자의 이름입니다. Kiwoom 클래스의 _receive_tr_data 메서드에서 'opt10081_req'라는 문자열로 TR을 구분했기 때문에 같은 이름으로 TR을 요청해야 합니다.

# opt10081 TR 요청
kiwoom.set_input_value("종목코드", "039490")
kiwoom.set_input_value("기준일자", "20170224")
kiwoom.set_input_value("수정주가구분", 1)
kiwoom.comm_rq_data("opt10081_req", "opt10081", 0, "0101")

while kiwoom.remained_data == True:
    time.sleep(TR_REQ_TIME_INTERVAL)
    kiwoom.set_input_value("종목코드", "039490")
    kiwoom.set_input_value("기준일자", "20170224")
    kiwoom.set_input_value("수정주가구분", 1)
    kiwoom.comm_rq_data("opt10081_req", "opt10081", 2, "0101")

TR을 요청할 때는 먼저 한 번 요청을 한 후 while 문을 사용해 인스턴스의 remained_data 값이 True인 경우 연속조회 데이터가 존재한다는 것을 의미하므로 다시 한 번 동일한 TR을 요청하도록 구현합니다. 키움증권은 1초에 최대 5번의 TR 요청만 허용하고 있으므로 time 모듈의 sleep 함수를 통해 0.2초를 대기한 후 다음 TR을 요청하도록 구현했습니다.1

연속조회를 할 때 주의할 점은 comm_rq_data 메서드의 세 번째 인자 값이 처음 요청할 때는 0이지만 두 번째부터는 2를 전달해야 한다는 점입니다. 모든 코드가 이해됐다면 예제 17.3의 코드를 실행해 봅니다. 그림 17.24와 같이 일봉 차트 데이터가 정상적으로 출력되는 것을 확인할 수 있습니다.
