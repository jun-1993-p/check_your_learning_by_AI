# 03: LLM이 쓴 빈칸이 2개 이상이면 거절 + 프롬프트 안내

**What to build:** `딕셔너리 ____에서 '____'의 Value를 얻기 위해 ____['____']을 사용한다.`(정답 a)처럼 LLM이 서로 다른 자리에 빈칸을 여러 개 쓴 문제는 학습자에게 나가지 않아요. 밑줄을 정규화한 뒤 LLM이 직접 쓴 빈칸이 2개 이상이면 출제 오류(`BlankError`)로 거절해요. 그러면 앱은 "빈칸 오류(…)"로 기록하고 같은 출처의 다음 문단으로 재시도하고, 평가는 기존처럼 다음 순위로 넘어가요. 같은 정답 단어를 코드가 함께 가려서 빈칸이 여러 개가 되는 경우는 계속 허용해요. 빈칸 유형 프롬프트에는 "정답 자리는 `____` 하나만 쓰고, 같은 단어가 또 나오면 그대로 둬(코드가 가린다)"는 취지를 넣어 재시도 호출을 줄여요.

명세: `.scratch/blank-validation/spec.md`

**Blocked by:** 02 (긴 밑줄 정규화가 먼저여야 긴 밑줄 하나를 빈칸 2개로 잘못 세지 않아요. 테스트 파일도 02에서 만들어요.)

**Status:** closed

- [x] 긴 밑줄 2덩어리 → `BlankError`

- [x] 앱의 근거 검사에서 이 오류가 "빈칸 오류(…)"로 기록되고, 재시도 흐름·평가 결과 CSV 열은 바뀌지 않아요
- [x] 앱 빈칸 유형 지시문에 빈칸 하나 안내가 들어가고, 평가 출제 프롬프트에도 같은 취지가 없으면 맞춰요 (풀이 LLM 프롬프트는 그대로)
